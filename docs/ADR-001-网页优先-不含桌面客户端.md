# ADR-001｜首发范围：删除桌面客户端，本地安装能力以 CLI 形态前置

- **状态**：提议中（Proposed）→ 你确认后转 Accepted，并合入 PRD/TDD 升 V0.2
- **日期**：2026-11-19
- **影响章节**：§1.2、§5（F-10~F-13、F-17）、§9.1、§10、§14 全章、§20、§21、D-02、D-07
- **一句话**：首发不写任何客户端代码；把"本地安装"从 Tauri 桌面应用降级为 `npx` 一条命令，GUI 推迟到有明确需求信号之后。

---

## 1. 问题

V0.1 把桌面端拆成两段：S3「Windows 客户端（登录/浏览/复制/下载/签名升级）」定 P0，S4「本地 Skill 安装管理」定 P1。这个拆法有两个问题：

1. **S3 没有独立价值。** 它交付的四项能力（登录、浏览、复制、下载）浏览器全部覆盖且体验更好。S3 唯一不可替代的价值在 S4，但 S4 被排在后面 —— 等于先花 4~6 周造一个"为了装 S4 而存在的壳"。
2. **它把两个假设绑死了。** 首发要验证的是「用户愿意来取资源」；S3 顺带把「用户愿意装一个 EXE」也变成了前提。一旦数据不好，无法判断是内容不行还是没人愿意装。

---

## 2. 决策

| 项 | 原方案 | 新决策 |
|---|---|---|
| 首发客户端 | Tauri 桌面端，P0（S3） | **删除**。首发零客户端代码 |
| 本地安装 | Tauri GUI 安装管理器，P1（S4） | **CLI**，P1（S4′），3~5 人日 |
| GUI 安装器 | — | P2，等 CLI 被真实使用后再做 |
| 技术栈 | Tauri 2 + React + Rust | 首发移除；CLI 用 Node（TypeScript），`npx` 分发 |
| 桌面端在首发中的角色 | 付费理由 + 品牌存在感 | 首发不收费（见决策 3），不需要这个角色 |

**新的一句话定位（客户端相关部分）**：平台是 Web 站；本地能力只有一条命令，负责"把文件放到正确位置、能回滚、能跟着上游更新"。

---

## 3. 理由

1. **成本差一个数量级。** Tauri 首发要同时搞定：WebView2 依赖、双端登录（loopback/深链）、minisign 更新通道、Authenticode 云签名、SmartScreen 信誉、Windows 安装器、更新失败处理、干净机测试。这些每一项都与内容价值无关，且做错一项就掉用户。Node CLI 只需要：登录一次、拉 manifest、校验哈希、写文件、记 registry。
2. **目标用户必然装了 Node。** 首发要适配的工具是 Claude Code / Codex / Cursor —— 这些工具的运行前提就是 Node ≥ 18。所以 `npx @researchhub/cli install <slug>` 对 100% 的目标用户是零前置成本的；相比之下"下载 EXE → 过 SmartScreen → 安装 → 授权目录"是五步摩擦。
3. **`npx` 顺带消掉三个难题。** 无 EXE 下载 → 无 SmartScreen 拦截；无安装器 → 无卸载残留/注册表问题；无 GUI → 无 WebView2 兼容矩阵。签名与更新通道整体移出首发范围。
4. **安全面反而更小。** CLI 按 manifest **逐文件下载**，不解压 ZIP → Zip Slip、绝对路径逃逸、符号链接逃逸、解压炸弹这一整类风险直接不存在（见 §5.4）。V0.1 §14.2 里最复杂的一段安全设计可以删掉。
5. **与决策 2、3 咬合。** 首发不收费（决策 3）→ 不需要"桌面端"充当付费理由；默认只索引（决策 2）→ 托管量很小 → 安装量也小 → 更不需要重型安装器。

## 5. 新形态定义：`@researchhub/cli`

### 5.1 命令集（v1，只此八个）

```
npx @researchhub/cli login                      # 浏览器授权（device code），token 存系统凭据库
npx @researchhub/cli doctor                     # 探测已安装工具与默认目录
npx @researchhub/cli install <slug>             # 预览 → 交互确认 → 安装
npx @researchhub/cli install <slug> --yes       # 非交互（脚本化）
npx @researchhub/cli list                       # 本机已装清单与版本
npx @researchhub/cli check-update               # 对比服务端最新版本
npx @researchhub/cli upgrade <slug>             # 升级（同样的预览/备份/回滚流程）
npx @researchhub/cli uninstall <slug>           # 仅删除登记内且未被本地改动的文件
npx @researchhub/cli rollback <slug>            # 回滚到上一个备份
```

### 5.2 安装流程

```
install <slug>
  → 解析 slug → GET /resource-versions/{id}/manifest?tool=claude-code
  → 校验 entitlement（若为 PRO）+ 资源状态（下架则拒绝）
  → doctor 探测目标目录（未探测到则提示用户输入/选择）
  → 打印变更预览：新增 N / 覆盖 M / 冲突 K（本地被改过的文件单独标红）
  → 用户确认（或 --yes）
  → 逐文件下载到临时目录，逐个校验 sha256
  → 备份被覆盖文件到 %LOCALAPPDATA%\ResearchHub\backups\<slug>\<version>\<ts>\
  → 原子 rename 落位
  → 写 registry（slug、tool、version、target_dir_hash、文件清单哈希、时间）
  → 失败则按备份自动回滚
```

### 5.3 本地登记（唯一状态源）

`%LOCALAPPDATA%\ResearchHub\registry.json`，字段：`slug / tool_key / version / install_dir / files[{path, sha256}] / installed_at`。**不记录、不上传本地绝对路径**；服务端只收匿名事件 `{slug, version, tool, result}`。

### 5.4 安全边界（比 ZIP 方案更薄）

- 逐文件下载，**不解压任何压缩包** → 无 Zip Slip / 解压炸弹 / 符号链接逃逸。
- 每个文件落盘前：路径规范化 + 拒绝绝对路径与 `..` + sha256 比对 + 单文件大小上限。
- **绝不执行**包内任何脚本（`.ps1/.bat/.exe/.py` 只当普通文件复制，并在预览里明确标注"本工具不会执行它"）。
- 写入只发生在用户确认的目录内；卸载只删登记内且哈希未变的文件，用户改过的一律保留并提示。

### 5.5 契约增量（3 个）

| 接口 | 权限 | 用途 |
|---|---|---|
| `GET /resource-versions/{id}/manifest?tool=` | 公开/按权益 | 文件清单 + 每文件签名 URL + sha256 + license + variant |
| `POST /cli/device-authorize`、`/cli/device-token` | 公开 | device code 授权（RFC 8628），避免 CLI 里输密码 |
| `POST /events` | 公开 | 匿名埋点（复制/下载/安装成功），北极星指标用 |

`manifest` 示例：

```json
{
  "slug": "hsi-paper-review", "version": "1.2.0",
  "tool_key": "claude-code", "variant": "claude-code@1",
  "install_root_hint": "%USERPROFILE%\\.claude\\skills\\hsi-paper-review",
  "license": { "spdx": "MIT", "file": "LICENSE" },
  "files": [
    { "path": "SKILL.md", "sha256": "…", "size": 4123, "url": "<1–5 分钟签名 URL>" }
  ],
  "warnings": ["包含 scripts/verify.py，CLI 不会执行它"]
}
```

## 6. 工期与验收

| 任务 | 估时 |
|---|---|
| 命令骨架 + 参数解析 + 配置/凭据存储 | 0.5 人日 |
| device code 登录 | 0.5 人日 |
| manifest 拉取 + 逐文件下载 + sha256 | 1 人日 |
| 预览 / 备份 / 原子写入 / 回滚 / registry | 1 人日 |
| `doctor` 工具目录探测 + 错误文案 | 0.5 人日 |
| `check-update` / `upgrade` / `uninstall` | 0.5 人日 |
| 打包发布（npm + 版本号 + 一个 smoke test） | 0.5 人日 |
| **合计** | **4~5 人日** |

**必须通过的用例（缺一不放行）**：
1. 干净 Windows 机器，只装了 Node + Claude Code，一条命令装成功。
2. 目标目录已有同名文件 → 预览显示"覆盖"，确认后备份、覆盖、可回滚。
3. 用户手改过 SKILL.md 后再升级 → 标记冲突、保留用户改动、不静默覆盖。
4. 下载中断网 → 报错退出，临时目录清理，registry 不变。
5. 文件 sha256 不匹配 → 中止，不落盘。
6. 已下架资源 → 拒绝安装，并给出人话解释。
7. 未登录 / 权益过期（PRO 资源）→ 提示登录或说明原因，不静默失败。

## 7. 风险与止损

| 风险 | 应对 |
|---|---|
| 用户嫌"命令行"不友好 | 目标用户是 Claude Code/Codex/Cursor 用户，命令行是其日常；若 30 天内 install 命令失败率 >20%，再考虑 GUI（F-19） |
| 用户机器 Node 版本过低 | `doctor` 首检 Node ≥18，给出升级指引 |
| 企业代理/内网 | 支持 `HTTPS_PROXY`；失败文案给出可诊断信息 |
| 失去"桌面端"叙事（对外宣传、付费理由） | 首发本就不收费；对外话术改为"一条命令装好"，比"下载客户端"更符合开发者习惯 |
| CLI 安装被滥用（爬取全部资源） | 安装接口同样限流 + 需登录；免费资源可放宽 |

---

## 8. 本决策的连带影响（需要你一并确认）

1. **monorepo 简化**：不再有第二个 React 宿主 → `packages/ui` 可删，§10 的目录结构可以砍掉一层。
2. **FastAPI 存废的讨论变简单了**：原本"Web 与桌面共享 TS 组件/SDK"是保留双栈的一个理由，现在这个理由消失。第 2 条决策（砍不砍 FastAPI）可以更干脆地按"你更熟哪种语言"来定。
3. **§14 整章降级**，但**不要删**：GUI 版设计（Capability、Updater、Authenticode）是真实资产，等有信号时直接拿回来用。
4. **§19.2 发布门槛**里的"Windows 安装/登录/下载/升级在干净机器测试通过"改为"CLI 七条用例通过"。

# 代码复现测试

## 立场

「跑通」不是结论，**可重复的数值一致性**才是结论。因此本技能的核心不是调试技巧，而是把「一致」定义清楚：对什么、用什么容差、在多少次重复上判断。

第二原则：**逐层验证，失败即停**。在环境不稳、冒烟未过的情况下跑端到端，得到的数字没有解释价值。

## 工作流程

### 第 0 层：环境复现
- 锁定依赖版本（锁文件/镜像），记录硬件与驱动
- 记录数据版本（哈希或版本号）与获取方式
- 完成判据：同一环境下连续两次运行冒烟测试，结果一致

### 第 1 层：冒烟测试
用最小数据（子集、少 epoch、小分辨率）在合理时间内跑完一次完整前向+反向+评估。完成判据：无报错、输出形状与类型正确、指标明显优于随机水平。这一层的目标只是「管道通畅」，不对数字做判断。

### 第 2 层：模块对拍
把流程拆成可单独验证的模块（数据加载与预处理、模型构建、损失、评估指标、后处理），逐个与参考实现比对中间产物。每个模块定义自己的判定口径：
- 数据处理：划分后样本数、标签分布、样本索引列表是否逐条一致
- 模型：参数量、某层输出张量的形状与首行数值（容差见下）
- 指标：用固定输入构造的小用例，与手算或参考实现比较

### 第 3 层：端到端对齐
按「趋势 → 排序 → 单指标 → 全指标」的顺序推进，不要在第一步就要求绝对值完全一致。

### 容差定义（必须写死）
- 浮点中间产物：相对误差 `|a-b| / max(|a|, 1e-8)` 或绝对误差，给出阈值并说明依据
- 最终指标：以原始报告的有效位为准，通常保留 2–3 位有效数字后比较
- 类别预测：一致率（例如 top-1 标签一致率 ≥ 99%）
- 随机性：固定种子后要求可重复；未固定种子时用 N 次运行的均值±标准差比较

判定口径：若参考实现未报告多次运行的波动，就不能要求你的结果落在其单点值的很小范围内——此时该用「趋势与排序一致」作为主判据，并在报告中说明。

### 差异归因
对每一处不一致，按六类归因并要求给出判别方法：数据版本与划分、预处理实现、超参与训练轮次、随机性与种子、库版本与硬件、报告口径（最优折/平均/单次）。每项标记「已验证/未验证」。

### 回归测试固化
把已验证的检查写成可重复运行的测试脚本（断言数值、形状、指标区间），纳入日常运行；任何后续改动都要跑一遍。要求：测试能在几分钟内跑完，否则不会有人跑。

## 硬性约束

- 不虚构原始报告指标、运行时长与结果数值；缺失一律 `[待补]`。
- 不把「趋势一致」表述为「完全复现」，两者必须分开报告。
- 不为对上数字而建议无限调参；若用户有此倾向，先纠正方法。
- 提醒确认第三方代码与数据的许可条款。

## 做不到什么

- 不运行代码：所有断言、容差与结论都需要你实际执行后确认。
- 不保证跨硬件完全一致：浮点累加顺序、并行归约、cuDNN 算法选择都会造成微小差异，只能界定容差。
- 无法判断方法本身是否正确：数值对齐只说明实现一致，不说明方法有效。
- 不修复原论文的代码缺陷：发现与论文描述不符时，只能记录并建议联系作者。

# 数据清洗与缺失值处理

## 立场

清洗的目的不是让数据「看起来完整」，而是让后续的统计推断仍然有效。任何一步操作都要能被另一个人在不看你的情况下重做，并且结果相同——做不到这一点，就是没洗干净。

顺序是这个技能的核心约束：**体检 → 机制 → 策略 → 划分 → 编码 → 留痕**。顺序错了，后面的努力基本白费。

## 工作流程

### 第一步：字段体检
逐列过一遍，记录四件事：类型（连续/计数/分类/时间/文本）、取值域与异常值、缺失率、是否有逻辑矛盾（年龄为负、出院早于入院、重复主键）。判定口径：缺失率 > 50% 的列先讨论是否保留，不要默认填补。

### 第二步：缺失机制判定
按三种可能给出判定与依据，不接受无依据的断言：
- **完全随机缺失（MCAR）**：缺失与任何观测变量无关。检验方向——把「是否缺失」当作二分类变量，与其他变量做关联检验；若普遍无关联，倾向 MCAR。
- **随机缺失（MAR）**：缺失可由其他观测变量解释。检验方向——缺失指示变量与观测变量存在可解释的关联，但控制这些变量后与缺失值本身无关。
- **非随机缺失（MNAR）**：缺失与未观测到的值本身有关（例如重症患者更少做某项检查）。这种机制无法用数据本身证明，只能靠领域知识与敏感性分析处理。

判定要求：写明「据此判为 X，依据是什么，什么证据会推翻这个判断」。

### 第三步：处理策略
按机制与缺失率选择，并同时给出主分析与敏感性分析两条路径：
- 完整案例分析：适合缺失极少且倾向 MCAR，需报告因此损失的样本量
- 单值填补（均值/中位数/众数）：只在变量独立性可接受且用于描述性目的时使用，会低估方差，不做假设检验时慎用
- 回归/热平台/近邻填补：需说明辅助变量选择的依据
- 多重插补：报告插补次数、插补模型、以及如何在插补数据集上合并估计
- 模型内处理：树模型的原生缺失处理、含缺失的似然方法，需说明实现
- 缺失作为信息：将「是否缺失」作为指示变量纳入模型，适合 MNAR 风险高的场景

### 第四步：划分与泄漏检查（硬性顺序）
先划分训练/验证/测试集，再做任何基于数据分布的变换（标准化、归一化、插补、编码、特征选择）。所有拟合类预处理只能在训练集上拟合，然后应用到验证与测试集。写作要求：把这句话明确写进方法部分。

### 第五步：异常值与编码
区分三种情况：录入错误（改正并留痕）、物理不可能值（置为缺失并记录）、真实的极端值（保留，或说明按何规则缩尾）。分类变量编码需写明参照组；时间变量需写明时区与精度。

### 第六步：留痕
每个变量、每步操作、每个参数都要写进决策日志：谁改的、何时、为什么、影响多少行。

## 硬性约束

- 不生成任何伪造的数据值、缺失率或统计量；用户未提供的数字一律写 `[待补：…]`。
- 不在未判定缺失机制的情况下直接推荐多重插补。
- 必须明确要求「先划分后插补」，若用户的流程相反，先指出问题再继续。
- 涉及个人信息、临床数据时，提醒按机构伦理与数据管理规定处理，不代替合规审查。

## 做不到什么

- 看不到你的数据：缺失模式、异常值分布的真假只能靠你提供的统计与样本判断。
- 不做 MNAR 的定量校正：只能给出敏感性分析的框架，阈值与结论要你自行设定。
- 不保证插补后估计无偏：多重插补的正确实现依赖插补模型设定，这个设定必须由懂领域的人定。
- 不替代统计咨询：涉及复杂抽样设计、权重、聚类结构时，建议找统计合作者复核。

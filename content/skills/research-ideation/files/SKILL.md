# 从已有成果到可发表方向

## 立场

方向不是想出来的，是**从资产里长出来的**。你要做的是把用户手上已有的东西摊开，找出其中没被榨干的部分，而不是给一堆"热门方向"。

## 第一步：资产盘点

逐项问清楚并列表：

- **数据**：规模、来源、标注情况、是否可公开、有没有别人也用同一份数据
- **代码**：可复用的模块、已验证的流程
- **结果**：跑过但没写出来的实验，包括负数结果
- **能力**：会什么方法、熟悉什么工具
- **资源**：剩余时间、算力、经费、合作者

负数结果常是被忽略的资产：它能支撑"哪种做法不奏效"的论文。

## 第二步：生成方向

基于资产生成 4–6 个方向，每个方向写：

- 一句话主张（能成为标题的那句）
- 需要哪些现有资产、还缺什么
- 预期贡献类型（新方法 / 新数据 / 新结论 / 复现与批判 / 应用）

## 第三步：三维排序

对每个方向打分（1–5）并给理由：

- **新颖性**：与已知工作的距离（你必须提示用户自行检索确认）
- **可行性**：用现有资产能否在 3 个月内出初稿
- **风险**：结果不确定的程度，以及失败时还剩什么可发表

排序结果用表格给出，不要含糊地并列。

## 第四步：为第一名设计最小验证

- 一句话假设
- 需要的最小实验（几组、多少样本、跑几次）
- 成功判据与失败判据
- 预计耗时
- 如果失败，退到哪个方向

## 第五步：诚实提醒

指出哪些方向看起来漂亮但**你已经能判断做不成**，并说明理由。不要为了让用户开心而把所有方向都说得很有希望。

## 输出格式

~~~
【资产清单】数据 / 代码 / 结果 / 能力 / 资源
【方向表】方向 | 新颖性 | 可行性 | 风险 | 需要的资产
【排序】1. … 理由 2. …
【最小验证】假设 / 实验 / 判据 / 耗时 / 退路
【我不建议的方向】… 因为 …
~~~

## 硬性约束

- 不虚构领域现状；提到"尚无人研究"必须写成"需要你检索确认"。
- 不承诺一定能发表。
- 创意可以大胆，但可行性判断要保守。
